# AI Modes Implementation Plan (Plans 2–4)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add the two Claude-powered ways to play — **The Open World** (sandbox, Timeless or Timed, invented characters) and **The Guided Tale** (authored scenes verbatim with Claude-written interludes) — running through `claude -p` on the owner's computer, with a validated reply contract and layered context/memory so characters stay in character and the world remembers.

**Architecture:** The Electron main process owns a Claude bridge that spawns `claude -p` (no tools, no settings, empty working folder) and returns `structured_output`. The renderer builds a fresh layered prompt per turn from canon, the played record and this save's playthrough memory; every reply is validated against a schema and canon, and only accepted proposals become deterministic engine commands. Guided builds on the Book reader; the Open World builds on Live the world; both use the Lamplight patterns (`ThinkingVeil`, `StoryInput`, `ModeChoice`).

**Tech Stack:** Electron IPC, Node `child_process`, React 19, the existing deterministic engine, `node:test`, Playwright (browser with an injected fake bridge; Electron with a fake `claude` executable).

**Spec:** `docs/superpowers/specs/2026-10-16-desktop-and-ai-modes-design.md` (sections "Claude bridge", "Reply contract", "Context and memory management", "Mode 2: Guided AI", "Mode 3: Sandbox AI", owner decisions). Visual rules: `docs/superpowers/specs/2026-10-17-lamplight-visual-design.md`, `DESIGN.md`.

## Global Constraints

- Prebuilt modes (Book, Live) never call Claude and behave exactly as before; their saves migrate to v5 unchanged in meaning.
- Three information tiers never mix: canon (repo, read-only), played record (engine state), invented (AI saves only, every entry tagged `source: 'invented'`).
- No new places: Claude may only use existing location IDs. Invented people are allowed (text-only, with a visual description), save-scoped, capped.
- Claude never edits state directly; every effect is a typed, bounded proposal validated by the engine. A rejected proposal never blocks valid narration.
- Writing uses the strongest model (default `opus`); housekeeping (chronicle summaries, memory extraction, mapping typed answers to authored options) uses a mid-tier model (default `sonnet`) — both selectable in Settings.
- Bridge invocation: `claude -p` with prompt on stdin, `--output-format json`, `--json-schema <schema>`, `--tools ""`, `--strict-mcp-config`, `--setting-sources ""`, `--no-session-persistence`, `--system-prompt <rules>`, `--model <model>`, cwd = an empty folder under userData. Never `--bare` (subscription login only works without it). Read `structured_output`; `is_error: true` is a failure.
- One request at a time per save; cancellable; generous timeout (240 s story, 120 s housekeeping); one retry with validation errors appended, then a graceful fallback that leaves the save unchanged.
- Guided: authored sections play verbatim; Claude writes only between/around them; typed answers at authored decisions map to an authored option; only authored endings.
- Sandbox: Timeless (mystery moves only when pursued) or Timed (mystery follows the calendar, renewal deadline 21 June 2027), chosen at start; Timeless → Timed is one-way, from the menu or an in-world proposal the player confirms.
- Nothing private in Git: prompts, replies and debug logs live under userData only (debug log off by default).
- Lamplight UI rules apply (tokens, vines for primary/focus only, AA contrast in all modes, reduced motion).

## Review Focus

1. **Claude missing, not logged in, or out of usage mid-turn** — a calm in-world message, the player's text kept in the box, the save unchanged, retry possible (tests in Task 2 and Task 7).
2. **A malformed or hostile reply** (unknown character, invented location, bond +50, 40 proposals, missing fields) — valid narration still shows, bad proposals are dropped, the save stays valid (test in Task 4).
3. **A very long playthrough** (300 turns) — the save stays under its size cap, the prompt stays within budget, open threads and high-importance events are always included (tests in Task 3 and Task 5).
4. **Closing the window or cancelling mid-request** — the `claude` child process is killed, no half-applied turn (test in Task 2).
5. **Old Book/Live saves** — migrate to v5 untouched and still never show AI controls (test in Task 3).
